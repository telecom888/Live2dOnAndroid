# 代码审查与 LLM 错误显示（1.1.1）

## 1.1.2 补充修复

- 用户复测发现完整对话页不显示 HTTP 错误。排查确认：`ConversationManagerScreen` 没有渲染 `ChatUiState.error`；1.1.1 仅补齐悬浮聊天、桌面聊天及多角色讨论入口，遗漏了完整对话页。请求层已有 HTTP 状态码传播，但该页面没有展示出口。
- 完整对话页与悬浮聊天共用错误组件，显示状态码和脱敏后的服务端详情，支持滚动及重试；错误区域在消息搜索和键盘打开时也保留。
- 移除对话气泡及桌面输入窗的“思考中”和旋转进度提示；保留实际回复流和原有思维链折叠。
- 新增本地 HTTP 403 回归测试，覆盖流式/非流式请求及 JSON、纯文本、空错误体，共六种组合。49 项单元测试全部通过；Lint 0 errors / 21 warnings；签名 Release APK 构建及签名验证通过。
- 本次本地 APK 复用未修改的原生库，未连接 Android 设备，尚未完成真机界面验证。这些测试证明请求错误能传到展示状态所用的消息转换函数，不能替代真机 UI 测试。

审查覆盖 LLM 流式/非流式请求、普通聊天、桌面聊天、多角色讨论、请求取消与错误展示，并结合全项目引用检索、编译、单元测试和 Android Lint 检查死代码及兼容性。

| 问题 | 修改 |

## 后续优化建议

- **P2：多角色讨论结束标记会丢失同条最终消息。** `LineOrchestrator.Decision.reply()` 遇到 `[scene_end]` 直接返回 END，外层 END 分支未发送 `decision.messages`。应把“发送消息”和“发送后结束”分开建模，并增加结束标记的行为测试。此次未修改讨论协议。
- 聊天历史及多角色讨论的 JSON 读写仍有主线程调用。可进一步统一存储层的 IO 调度，避免大型会话卡顿。
- 推理文本逐片段拼接、立即刷新 StateFlow，长推理时会重复分配字符串并触发高频重组。建议用缓冲区并复用正文的节流发布机制。
- `SettingsScreen.kt` 和 `Live2DChatOverlay.kt` 体积较大，可按设置子页、消息行和错误组件拆分；不宜在错误修复中一次重写。
- Lint 仍有 21 项非阻塞告警，主要为权限声明、新系统照片访问、无障碍点击、默认 Locale 和 Compose 参数顺序。未因“无引用”检索结果盲删 Android 生命周期回调、原生桥接接口或可能被测试使用的 API。
